title: "Automatic benchmarks"
description: "Turn a system prompt, policy documents and tool schemas into a covering, validated, mutation tested benchmark suite."
icon: "wand-magic-sparkles"
---

A real system prompt covers many topics, rules, formats and refusal boundaries. Writing a suite by hand that covers all of them under realistic and adversarial conditions takes days, and nobody can say which rules were never tested.

GitGrounded treats the prompt as a specification and applies three software testing techniques to it: **covering arrays** for input conditions, **oracles** derived from the source text, and **mutation testing** to prove the suite catches real faults.

## Quick start

```bash
gitgrounded discover --suite auto
gitgrounded synth --suite auto
gitgrounded suite review --suite auto
gitgrounded mutate --suite auto --max-mutants 20
gitgrounded suite coverage --suite auto --open
gitgrounded run --suite auto --base main --minimal
```

## Pipeline

<Steps>
  <Step title="Ingest" icon="file-import">
    The system prompt, documents and MCP tool lists are split into sentences with stable ids such as `prompts/system.txt#main:4`.
  </Step>
  <Step title="Extract behaviors" icon="list-check">
    A generator model turns sentences into atomic, testable behaviors with a kind, severity, observable success criterion and the source ids they come from. Behaviors that cite no real sentence are dropped. A second pass adds implicit behaviors (out of scope requests, prompt injection, ambiguous requests). Near duplicates are merged by embedding similarity. Behavior ids are hashes of their statement, so they stay stable across runs.
  </Step>
  <Step title="Choose dimensions" icon="sliders">
    Conditions under which inputs vary: style, language, difficulty, adversary type, number of turns. Override or extend them in `coverage.dimensions`. App specific dimensions are proposed too; set `apply_proposed_dimensions: true` to use them.
  </Step>
  <Step title="Plan" icon="table-cells">
    For each behavior, a greedy covering array of strength 2 (or 3) over the relevant dimensions guarantees every pair of conditions appears at least once. Budget is allocated by severity. The first cell is always a clean baseline so failures can be attributed to conditions.
  </Step>
  <Step title="Synthesize" icon="pen">
    One call per behavior writes an input for every cell plus expectations (the oracle) derived only from the behavior's source text.
  </Step>
  <Step title="Validate" icon="shield-check">
    A second model drops cases whose expectations invent rules, that do not target the behavior, or that are unanswerable.
  </Step>
  <Step title="Diversify" icon="shuffle">
    Shingle Jaccard removes near duplicates, then maximal marginal relevance over embeddings picks the final set per behavior.
  </Step>
  <Step title="Mine logs (optional)" icon="chart-line">
    Production messages are redacted, clustered and mapped to behaviors. Clusters without a behavior are reported as untested traffic; behaviors without traffic are reported too.
  </Step>
  <Step title="Mutate" icon="bug">
    The prompt is broken on purpose: delete a rule, negate it, weaken it, change a number, drop a section, downgrade the model. Each mutant is run against the suite. Mutation score is the share of mutants the suite detects. Surviving mutants trigger targeted synthesis once; new cases that detect the mutant are added.
  </Step>
  <Step title="Minimize" icon="compress">
    Greedy set cover keeps the smallest suite that detects the same mutants with at least the minimum cases per behavior. Use it in CI with `gitgrounded run --minimal`.
  </Step>
  <Step title="Review" icon="user-check">
    `gitgrounded suite review` opens a local page to accept, edit or reject cases with the keyboard. The reviewed share is reported in coverage.
  </Step>
  <Step title="Version" icon="code-branch">
    Every synth writes `.gitgrounded/suites/<name>/versions/vN`. On the next synth only behaviors whose statement or source text changed are regenerated. Use `--full` to regenerate everything.
  </Step>
</Steps>

## Configuration

```yaml gitgrounded.yml
suites:
  auto:
    target: app
    coverage:
      sources:
        system_prompt: prompts/system.txt
        documents: [docs/policy.md]
        tools: [tools.json]
        logs: logs/sample.jsonl
      dimensions:
        language: [en, hi]
        style: [terse, angry, typo_heavy, code_mixed_hinglish]
      strength: 2
      budget_cases: 150
      min_cases_per_behavior: 3
      mutation_target: 0.85
      mutation:
        target_file: prompts/system.txt
        model_file: config/model.yaml
        model_key: model
        downgrade_to: gpt-4.1-nano
```

| Key | Default | Meaning |
|---|---|---|
| `sources.system_prompt` | none | main prompt file |
| `sources.prompts` | `[]` | extra prompt files |
| `sources.documents` | `[]` | policy and knowledge files |
| `sources.tools` | `[]` | MCP `tools/list` JSON files |
| `sources.logs` | none | JSONL of production messages |
| `dimensions` | built in set | condition name to list of values |
| `use_default_dimensions` | `true` | keep the built in dimensions alongside yours |
| `propose_dimensions` | `true` | ask the generator for app specific dimensions |
| `apply_proposed_dimensions` | `false` | use the proposed dimensions automatically |
| `strength` | `2` | covering array strength (2 or 3) |
| `budget_cases` | `120` | total case budget |
| `min_cases_per_behavior` | `3` | floor per behavior |
| `oversample` | `1.5` | candidates generated per kept case before diversity selection |
| `diversity_lambda` | `0.7` | relevance versus diversity tradeoff in selection |
| `mutation_target` | `0.85` | mutation score that `mutate --fail-on target` requires |
| `mutation.operators` | all five | `delete_rule`, `negate_rule`, `weaken_rule`, `swap_value`, `drop_section` |
| `mutation.max_mutants` | `25` | cap on mutants per run |
| `mutation.target_file` | system prompt | file to mutate |
| `mutation.model_file`, `model_key`, `downgrade_to` | none | enable the model downgrade mutant |
| `mutation.repair_rounds` | `1` | synthesis rounds for surviving mutants |
| `seed` | `7` | planning seed |

`coverage` can also be set at the top level of `gitgrounded.yml` as a default for every suite.

## Import an existing suite

```bash
gitgrounded suite import --suite core --file old_cases.json
gitgrounded suite show --suite auto
```

`import` accepts JSON or JSONL and writes the suite's cases file. See [Case format](/docs/reference/cases).
