A `.ggb` file is a deterministic zip that lets anyone check that a GitGrounded result was not edited after it was produced and, when signed in CI, which workflow at which commit produced it.

```bash
gitgrounded run --base main --bundle
gitgrounded bundle --sign local
gitgrounded verify .gitgrounded/runs/*/evidence.ggb
```

## What a valid bundle proves

> Workflow W in repository R at commit C ran GitGrounded version V with config hash H on suite version S with dataset hash D at time T and produced exactly these records and this verdict.

## What it does not prove

<CardGroup cols={3}>
  <Card title="That the suite is fair" icon="scale-unbalanced">
    Mitigation: the suite, its coverage and mutation score travel inside the bundle, and the suite files are committed at that commit. Certificates also require an AI generated, sealed question set.
  </Card>
  <Card title="That the judge is right" icon="gavel">
    Mitigation: deterministic assertions, pairwise judging in both orders, judge panels, judge traps, calibration against human labels, and full transcripts inside the bundle.
  </Card>
  <Card title="That a local run is a CI run" icon="laptop">
    Local bundles are marked self signed and the verifier says so.
  </Card>
</CardGroup>

The accurate claim is **tamper evident and independently verifiable**, not tamper proof.

## Layout

```
manifest.json
records/cases.jsonl
records/transcripts.jsonl
records/judgements.jsonl
records/assertions.jsonl
inputs/config.resolved.json
inputs/change.diff
inputs/suite/current.jsonl
inputs/suite/coverage.json
inputs/suite/mutation.json
summary.json
merkle.json
report.html
signature/local.json or signature/manifest.sigstore.json
```

## Integrity

* Every record is canonical JSON: sorted keys, no whitespace, floats rounded to 6 digits.
* Merkle tree: the leaf hash is `SHA256(0x00 || line)`, the node hash is `SHA256(0x01 || left || right)`, an odd node is promoted. The root is stored in `manifest.json`.
* `manifest.json` lists the SHA256 of every other file and is itself canonical JSON.
* The signature covers the exact bytes of `manifest.json`.

## Signing

| Mode | When | Strength |
|---|---|---|
| `sigstore` | GitHub Actions with `id-token: write` | certificate bound to the workflow identity, logged in the public Rekor transparency log |
| `local` | developer machine | Ed25519 key in `~/.config/gitgrounded/keys/`, marked self signed |
| `none` | opt out | integrity only |

`sign: auto` picks Sigstore in GitHub Actions when available, otherwise local. Set it in `evidence.sign` or per run with `--sign`. The local key lives at `$XDG_CONFIG_HOME/gitgrounded/keys/ed25519.pem` and is created on first use; point `GITGROUNDED_SIGNING_KEY` at another file to use a specific key.

The [GitHub Action](/docs/ci/github) also creates an artifact attestation whose predicate is the manifest. See [Attestation format](/docs/attestation/eval-run/index).

## Verify

<Tabs>
  <Tab title="Command line">
```bash
gitgrounded verify run.ggb
gitgrounded verify run.ggb --identity https://github.com/OWNER/REPO/.github/workflows/gitgrounded.yml@refs/heads/main
gitgrounded verify run.ggb --public-key KEY_ID
gitgrounded verify run.ggb --require-signature --format json
```
  </Tab>
  <Tab title="GitHub attestation">
```bash
gh attestation verify run.ggb --repo OWNER/REPO
```
  </Tab>
  <Tab title="Browser">
    Drop the file on the browser verifier (`verifier/index.html`, also published at `/verify` on the project's GitHub Pages site). It recomputes every hash and the Merkle root and checks Ed25519 signatures client side. Nothing is uploaded.
  </Tab>
</Tabs>

### Statuses

| Status | Meaning | Exit code |
|---|---|---|
| `VERIFIED` | intact, Sigstore signature matches the expected identity | 0 |
| `VERIFIED_INDEPENDENT` | intact, signed by an independent certifier key you pinned | 0 |
| `VERIFIED_SELF_SIGNED` | intact, signed with a local Ed25519 key | 0 |
| `VERIFIED_INTEGRITY_SIGNATURE_PRESENT` | intact, CI signature present, identity not checked (pass `--identity`) | 0 |
| `VERIFIED_UNSIGNED` | intact, no signature | 0, or 3 with `--require-signature` |
| `SIGNATURE_INVALID` | the signature does not match the manifest | 1 |
| `TAMPERED` | a file, hash or Merkle root does not match | 1 |

## Redaction

Authorization style headers are always replaced by a salted HMAC before records are written. Add JSONPaths under `evidence.redact` to hide more fields. Records stay verifiable because redaction happens before hashing.

```yaml gitgrounded.yml
evidence:
  sign: auto
  include_transcripts: true
  redact:
    - $.request.body.user.email
    - $.output.account_number
```

Paths are matched against each transcript record, which holds the `request`, `raw_output` and `output` of a call.
