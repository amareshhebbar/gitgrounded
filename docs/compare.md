# Compare prompts and models, with a certificate

## Three commands

```bash
pip install "gitgrounded[sign]"
cp .env.example .env
gitgrounded compare --prompt v1.txt --prompt v2.txt --model openai --model claude --context policy.md --certify --open
```

Check setup first with `gitgrounded doctor --ping`.

## What happens

1. Every prompt goes into one locked question set. Behaviors are extracted from all prompts together, so neither prompt gets an advantage. Questions and expected answers are generated by the generator model, checked by the validator model, and sealed with a hash.
2. Every prompt is run on every model (a grid). The first candidate is the baseline; use `--baseline N` to pick another.
3. Each candidate is compared with the baseline: code checks, rubric judge, pairwise judge in both orders, confidence intervals, p values.
4. With `--certify`, the judge must first grade trap answers correctly (empty, off topic, ideal). If it fails, no certificate is issued.
5. The certificate bundle contains `certificate.json`, `certificate.html`, `traps.jsonl` and one signed evidence bundle per comparison. `gitgrounded verify` checks all of them.

## Rules for a certificate

| Rule | Why |
|---|---|
| Question set is AI generated and sealed | devs cannot pick easy questions; any edit breaks the seal |
| At least `evidence.certify.min_cases` questions (default 10) | small sets prove nothing |
| Judge trap accuracy at least `evidence.certify.trap_threshold` (default 90%) | proves the judge works on this run |
| Signed (Sigstore in CI, Ed25519 locally) | proves the result was not edited |
| Real models, not offline mode | mock runs are never certified |

Optional and shown on the certificate when present: human agreement from `gitgrounded calibrate`, mutation score from `gitgrounded mutate`.

## Same question set over time

The suite name is a hash of the prompts, context files, generator model and budget. Running the same comparison again reuses the same sealed questions, so scores stay comparable. Use `--regenerate` for a fresh set. A modified set is refused.

## Agents and tools

```yaml
targets:
  my_a2a_agent:
    type: a2a
    url: http://localhost:9999/
  my_adk_agent:
    type: adk
    base_url: http://localhost:8000
    app_name: my_agent
  my_mcp_server:
    type: mcp
    command: ["python", "server.py"]
```

A2A uses JSON RPC `message/send` and keeps `contextId` across turns. ADK uses the `adk api_server` session and `/run` endpoints and records tool calls, so `tool_called` and `tool_call_order` assertions work. Certify any of them with `gitgrounded synth --suite <name>` then `gitgrounded run --suite <name> --base main --certify`.
